## 决策 1：类型信息由 SemanticModel 统一提供

**确认内容**：

- AST 保持纯语法，不直接携带语义类型。
- `SemanticAnalyzer` 建立 `SemanticModel`，记录每个表达式/声明的 `types::Type`。
- `LLVMCodeGenerator` 接收 `SemanticModel`，只消费类型，不再根据初始化器形状或 LLVM 值反推类型。
- 所有 C^ 类型到 LLVM 类型统一经过 `TypeLowering`。
- 缺失类型直接报错，删除 `int32` 默认回退。
- 函数调用只使用 semantic 解析出的目标，codegen 不再自行拼 mangled name。
- 数组/切片/元组/类/引用/只读/可空的表示由 TypeLowering 统一决定。

**状态**：待实现。

## 决策 2：`defer` 是块级作用域

**确认内容**：

- `defer` 绑定到最近一层花括号作用域，而不是整个函数。
- 支持 `defer expr;` 与 `defer { ... }`。
- 同一作用域内的 defer 按 LIFO 执行。
- 循环体内的 defer 每次迭代注册、每次迭代结束执行。
- `return` / `throw` / `break` / `continue` 退出作用域时执行对应 cleanup。
- defer 与析构函数使用同一个 cleanup 栈，按注册/构造顺序统一 LIFO。
- defer 在异常展开中再次抛异常时 `terminate`。

**状态**：待实现。当前实现仍是函数级。

---

## 决策 3：RAII 覆盖栈上/late 对象，堆内存显式管理

**确认内容**：

- 栈上类值和 `late` 成功构造的对象在作用域退出时自动析构。
- 堆对象继续使用显式 `new/delete`。
- `new T[n]` 对非平凡类型逐元素构造；`delete[]`/删除 owning slice 时逐元素析构。
- 空指针 delete 为 no-op。
- `late T x;` 不要求默认构造；第一次赋值执行构造；只有成功构造的对象才析构。
- 使用未初始化 `late` 是编译错误。
- 析构函数不应抛异常；清理路径中抛异常统一 `terminate`。
- 数组元素、异常展开和移动语义分阶段实现。

**状态**：部分实现（显式 delete 已调用析构；自动析构待实现）。

## 决策 4：OOP 采用单继承 + 接口 + 可选虚方法

**确认内容**：

- `self` 是唯一实例关键字。
- `base` 用于基类成员访问和构造函数调用：`: base(args)`、`base.member`、`base.method()`。
- `super` 已移除；不保留第二个父类关键字。
- 不做多实现继承；保留多接口实现。
- 默认静态派发；`virtual` 显式开启动态派发，`override` 必须写。
- 有虚方法的类使用 vtable；接口值使用 fat pointer `{object*, itable*}`。
- 属性 getter/setter 遵循方法/继承/虚方法规则。
- static 字段为类级全局，静态方法没有 `self`，不能使用 `base`。
- 派生类构造函数按基类 → 派生类顺序执行，显式 `: base(...)` 或基类默认构造。
- 有虚方法的类需要虚析构（自动生成或显式声明）。

**状态**：`base` 统一已落地；单继承布局、静态派发、属性、static 已可用；vtable/接口动态派发待实现。

## 决策 5：范围统一为半开区间

**确认内容**：

- `a..b` 表示半开区间 `[a, b)`。
- `a..=b` 表示闭区间 `[a, b]`。
- `foreach`、切片、未来范围相关语法统一使用同一规则。
- 不再保留“foreach 闭区间、切片半开区间”的不一致。

**状态**：待实现。当前 `foreach` 仍是闭区间，且尚未支持 `..=`。
