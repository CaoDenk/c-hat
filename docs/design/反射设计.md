# C^ 语言反射设计文档

## 1. 设计目标

- **简洁优雅**：使用直观的语法实现反射功能
- **类型安全**：在编译时进行类型检查
- **表达能力强**：支持多种反射操作
- **少即是多**：通过统一的语法减少元数据复杂度
- **零标准库依赖**：核心反射功能不依赖标准库

## 2. 核心设计理念

### 2.1 统一的类型检查语法

使用 `is` 关键字实现类型特性检查，语法形式为：

```c^
type is kind
```

其中：
- `type` 可以是类型名称、类型变量或表达式
- `kind` 是类型特性，如 `struct`、`class`、`union`、`enum`、`primitive` 等

### 2.2 反射元数据访问

通过 `@` 操作符访问类型的元数据，语法形式为：

```c^
@type.property
```

### 2.3 编译时反射

所有反射操作都在编译时执行，生成相应的常量或代码。

### 3.2 元数据访问

```c^
// 获取类型名称
comptime const char* name = @T.name;

// 获取类型大小
comptime size_t size = @T.size;

// 获取类型对齐
comptime size_t align = @T.align;

// 获取类型的字段数量
comptime size_t field_count = @T.field_count;

// 遍历字段（推荐方式）
for (let f in @T.fields) {
  comptime const char* field_name = f.name;
  comptime auto field_type = f.type;
  // 处理字段
}

// 遍历方法
for (let m in @T.methods) {
  comptime const char* method_name = m.name;
  comptime auto return_type = m.return_type;
  // 处理方法
}
```

### 3.3 访问修饰符判断

使用 `access` 函数和 `is` 关键字检查访问修饰符：

```c^
// 检查访问修饰符
if (access(f) is public) {
  // 处理公共成员
} else if (access(f) is private) {
  // 处理私有成员
} else if (access(f) is protected) {
  // 处理受保护成员
} else if (access(f) is internal) {
  // 处理内部成员
}
```

### 3.4 成员类型判断

```c^
// 判断成员类型
for (let f in @T.fields) {
  if (f.is_property) {
    // 处理属性
  } else {
    // 处理成员变量
  }
}

// 遍历方法
for (let m in @T.methods) {
  // 处理方法
}
```

### 3.5 成员访问

使用 `@` 操作符访问实例的成员：

```c^
// 访问字段
auto value = instance.@field;

// 访问属性（自动调用 getter）
auto value = instance.@property;

// 设置属性（自动调用 setter）
instance.@property = value;

// 调用方法
auto result = instance.@method(arg1, arg2);
```

### 3.6 编译时反射应用

```c^
// 编译时类型判断
comptime if (T is struct) {
  // 结构体特化逻辑
} else if (T is class) {
  // 类特化逻辑
} else {
  // 其他类型逻辑
}

// 编译时生成代码
template <typename T>
func print_type_info() {
  comptime if (T is struct) {
    printf("Type %s is a struct\n", @T.name);
  } else if (T is class) {
    printf("Type %s is a class\n", @T.name);
  } else if (T is primitive) {
    printf("Type %s is a primitive type\n", @T.name);
  }
}
```

## 4. 元数据设计

### 4.1 核心元数据结构

使用统一的元数据结构，避免为每种类型特性单独设计字段：

```c^
struct TypeInfo {
  const char* name;           // 类型名称
  size_t size;                // 类型大小
  size_t align;               // 类型对齐
  size_t field_count;         // 字段数量
  size_t method_count;        // 方法数量
  FieldInfo* fields;          // 字段信息
  MethodInfo* methods;        // 方法信息
  // 类型特性通过 is 操作符检查，不存储为字段
};

struct FieldInfo {
  const char* name;           // 字段名称
  TypeInfo* type;             // 字段类型
  size_t offset;              // 字段偏移
  AccessModifier access;      // 访问修饰符
  bool is_property;           // 是否为属性
  const char* getter_name;    // getter 方法名称（如果是属性）
  const char* setter_name;    // setter 方法名称（如果是属性）
};

struct MethodInfo {
  const char* name;           // 方法名称
  TypeInfo* return_type;      // 返回类型
  TypeInfo** param_types;     // 参数类型
  size_t param_count;         // 参数数量
  AccessModifier access;      // 访问修饰符
  bool is_static;             // 是否为静态方法
  bool is_virtual;            // 是否为虚方法
};
```

### 4.2 类型特性检查实现

类型特性检查通过编译器内置的类型信息实现，不需要在元数据中存储额外的标志位：

```c^

}

  return type->kind == TypeKind::Class;
}

  return type->kind == TypeKind::Union;

```

## 5. 实现策略

### 5.1 编译期处理

1. **类型信息收集**：编译器在语义分析阶段收集类型信息，构建 TypeInfo 结构
2. **元数据生成**：为每个类型生成对应的元数据
3. **反射表达式解析**：解析 `@type` 和 `type is kind` 表达式
4. **编译时计算**：在编译时计算反射表达式的值，生成相应的代码

### 5.2 运行时支持

核心反射功能完全在编译时实现，不需要运行时支持。对于需要运行时反射的场景，可以通过编译时生成的代码实现。

## 6. 示例

### 6.1 序列化示例

```c^
// 通用序列化函数
template <typename T>
func serialize(T value) {
  comptime if (T is struct || T is class) {
    printf("{");
    bool first = true;
    for (let f in @T.fields) {
      // 只序列化公共成员
      if (access(f) is public) {
        if (!first) printf(", ");
        first = false;
        
        printf("\"%s\": ", f.name);
        
        // 处理属性和成员变量
        if (f.is_property) {
          // 调用 getter 方法获取属性值
          serialize(value.@f);
        } else {
          // 直接访问成员变量
          serialize(value.@f);
        }
      }
    }
    printf("}");
  } else if (T is primitive) {
    if (T is int || T is long) {
      printf("%d", value);
    } else if (T is float || T is double) {
      printf("%f", value);
    } else if (T is bool) {
      printf("%s", value ? "true" : "false");
    } else if (T is char) {
      printf("'%c'", value);
    }
  } else if (T is array || T is slice) {
    printf("[");
    for (size_t i = 0; i < value.length; i++) {
      serialize(value[i]);
      if (i < value.length - 1) {
        printf(", ");
      }
    }
    printf("]");
  }
}

// 使用示例
struct Person {
  string name;
  int age;
  bool is_student;
};

func main() {
  Person p = {"Alice", 20, true};
  serialize(p);
  // 输出: {"name": "Alice", "age": 20, "is_student": true}
}
```

        // 尝试其他构造方式

  }
};

### 6.3 依赖注入（自动注入字段）

```c^
// 依赖注入容器（自动注入字段）
template <typename T>
func create_instance() -> T {
  T instance;
  comptime if (T is struct || T is class) {
    for (let f in @T.fields) {
      if (access(f) is public) {
        // 自动注入依赖
        instance.@f = resolve_dependency(f.type);
      }
    }
  }
  return instance;
}

// 使用示例
class DatabaseService {
public:
  func query() { printf("Querying database\n"); }
};

class UserService {
public:
  DatabaseService* db; // 依赖项
  
  func get_user() {
    db->query();
  }
};

func main() {
  UserService service = create_instance<UserService>();
  service.get_user();
  // 输出: Querying database
}
```

## 7. 设计理念：少即是多

### 7.1 核心思想

"少即是多"（Less is More）是 C^ 语言反射设计的核心理念，通过简洁的语法和统一的机制，减少冗余复杂性，同时保持强大的表达能力。

### 7.2 实现策略

#### 7.2.1 统一语法与语义
- **统一类型检查**：使用 `is` 关键字作为唯一的类型特性检查语法
- **统一元数据访问**：通过 `@` 操作符统一访问所有类型的元数据
- **统一成员处理**：使用一致的方式处理不同类型的成员

#### 7.2.2 减少元数据冗余
- **隐式类型特性**：通过编译器内部类型信息推导，不存储冗余的类型标志位
- **统一成员表示**：通过不同的元数据数组区分成员类型，避免复杂的标志位
- **编译时计算**：利用编译时计算减少运行时开销

#### 7.2.3 抽象共通模式
- **统一访问修饰符处理**：通过 `access(f) is public` 语法统一处理访问修饰符
- **统一成员类型判断**：通过元数据结构和属性统一判断成员类型
- **编译时代码生成**：利用 `comptime` 生成针对性代码

#### 7.2.4 简洁的遍历语法
- **for...in 语法**：使用 `for (let f in @T.fields)` 遍历字段，避免手动管理索引
- **语义清晰**：语法接近自然语言，易于理解和记忆
- **类型安全**：编译时检查，避免运行时错误

### 7.3 优势

1. **语法简洁**：统一的 `is` 关键字、`@` 操作符和 `for...in` 语法
2. **类型安全**：编译时检查，避免运行时错误
3. **表达能力强**：支持多种反射操作，满足不同场景需求
4. **性能优化**：编译时计算，无运行时开销
5. **可扩展性**：统一的设计模式使添加新特性变得简单
6. **易于理解**：直观的语法和统一的机制，降低用户学习成本

### 7.4 劣势

1. **实现复杂度**：编译器需要实现复杂的类型信息收集和处理逻辑
2. **学习曲线**：需要理解编译时反射的概念和使用方法
3. **代码生成**：编译时生成的代码可能会增加可执行文件大小

## 8. 结论

通过 `T is struct`、`access(f) is public`、`for (let f in @T.fields)` 和 `instance.@member` 这样的语法设计，C^ 语言可以实现简洁、优雅的反射系统，同时保持类型安全和高性能。这种设计遵循了"少即是多"的原则，通过统一的语法减少了元数据的复杂度，使反射功能更加易于使用和理解。

反射系统的实现将为 C^ 语言带来更强大的表达能力，支持更多高级编程范式，如依赖注入、序列化/反序列化、ORM 等，同时保持语言的简洁性和性能优势。
