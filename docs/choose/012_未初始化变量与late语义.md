## 1. 背景

C^ 需要一种明确表示“预留存储但暂不初始化”的语法，避免普通变量和未初始化变量混在一起。
`late` 是这个入口，但仅凭语法不足以保证安全，必须配套初始化证明和析构规则。

---

## 2. 决策

### 2.1 非 `late` 局部变量必须初始化

所有非 `late` 的局部变量，声明时必须有初始化器：

```c^
func main() -> int {
    int x = 0;        // OK
    var y = 42;       // OK
    int z;            // Error: non-late variable must be initialized
    late int w;       // OK：明确表示预留内存、暂不初始化
    return x + y;
}
```

这意味着：

- `var x;` 不允许
- `let x;` 不允许
- `const int N;` 仍然不合法
- `int x = 0;` 是最常见写法

### 2.2 `late` 是唯一未初始化局部存储

```c^
late int x;   // 只预留存储，不初始化
late int y;   // 显式类型 + 未初始化
```

`late` 的作用不是“少写初始化值”，而是明确告诉编译器：

> 这个变量可能在后续某个路径上才构造，编译器必须证明使用前已初始化。

### 2.3 适用范围

这条规则主要针对**局部变量**。

- 函数参数：由调用方初始化，天然合法；需要跨函数初始化时使用 `out T&` 契约
- `for` / `foreach` 的迭代变量：由循环初始化语句/迭代过程初始化
- `match` 绑定变量：由模式匹配初始化
- `catch (T e)`：由异常 payload 初始化
- 全局变量：建议也必须初始化；如果允许未初始化全局，应单独设计，不混入 `late`
- 类字段：不适用这条规则，字段由构造函数或默认初始化规则处理；`late` 字段不建议支持

### 2.4 `late` 的赋值语义

- 如果变量未初始化：赋值是在预留空间上 **构造**
- 如果变量已初始化：赋值是正常赋值
- 对非平凡类型，重新赋值要先析构旧值，再构造/赋值新值
- 如果构造失败，旧值已析构，变量进入未初始化状态

### 2.5 definite assignment（变量级）

初始化状态是**变量级**的，不是元素级的。编译器必须证明：

- 读取 `x` 前所有路径都初始化了 `x`
- `x` 作为函数参数/返回值前已初始化
- `x` 在 `defer` 中使用时，所有能到达该 `defer` 的路径都已初始化

固定数组是一个整体值：

- 整体初始化/整体赋值才算初始化。
- 元素写入 `a[i] = ...` 不改变整个数组的初始化状态。
- `late T[N] a;` 在 `a = [value; N]` 或 `a = b` 前不能读取。

检查只在过程内进行，且循环保守：循环体内赋值不保证循环结束后已初始化。跨函数初始化不做推断，改用 `out T&` 契约。

### 2.6 析构规则

- `late` 对象的析构必须受初始化状态保护
- `try` 中初始化失败时，不析构
- `if/else` 只有一分支初始化时，后续使用应报错
- `catch` 可以作为初始化路径之一
- 只有成功构造的对象才参与析构

### 2.7 `late` 与 `defer`

`defer` 可以引用 `late` 变量，但只有在 `defer` 注册时该变量在所有到达路径上已初始化时才允许。

```c^
func test() {
    late int x;
    x = 10;
    defer println(x); // OK：x 在这里已确定初始化
}
```

如果 `defer` 注册在初始化之前，就不能引用 `x`。

### 2.8 v1 限制

为了避免一开始就把复杂度做爆，v1 建议只支持：

- 标量类型
- 简单 struct/class
- 固定数组（整体初始化）
- `if/else`、`try/catch`、顺序语句中的变量级 definite assignment

暂不支持或标记 experimental：

- 逐元素数组初始化证明
- 跨过程初始化推断（改用 `out T&`）
- 循环内 `late` 的复杂初始化合并
- `goto` 与 `late`
- `late` 与移动 `~`
- 带析构函数对象的 `out` 初始化/cleanup 注册
- `late` 与异常强保证

### 2.9 已确认补充决策

1. **`late` 只能用于局部变量。**
   - 不允许全局 `late`
   - 不允许类字段 `late`
   - 不允许函数参数 `late`
   - 不允许引用 `late T&`

2. **`late` 的声明形式。**
   - `late int x;` 合法
   - `late var x;` 非法（无法推导类型）
   - `late var x = expr;` 非法/冗余（有初始化器就不是未初始化）
   - `late let int x;` 合法：只允许一次初始化，之后不可重新绑定

3. **`late` 允许的类型。**
   - 标量
   - 简单 struct/class
   - 固定数组（整体初始化）
   - 不允许引用类型

4. **赋值语义。**
   - 未初始化：第一次赋值是构造
   - 已初始化：正常赋值
   - 非平凡类型重新赋值先析构旧值，再构造/赋值
   - 构造失败：变量进入未初始化状态

5. **析构。**
   - 只有成功构造的对象才析构
   - `try` 初始化失败不析构
   - `if/else` 只有一分支初始化时，后续使用报错
   - `catch` 可以作为初始化路径

6. **definite assignment（变量级）。**
   - 读取前所有路径必须初始化
   - 作为参数/返回值前必须初始化
   - defer 引用时，defer 注册点所有路径必须已初始化
   - 固定数组只有整体初始化/整体赋值才算初始化
   - 不做逐元素、跨过程、切片别名分析

7. **循环与 goto。**
   - v1 允许循环内 `late` 只在循环体内使用
   - 循环后使用 `late` 需要循环前已初始化，或循环保证至少执行一次（v1 不证明后者）
   - 循环内赋值不自动证明循环后已初始化
   - `goto` 与 `late` 标记 experimental

8. **`late` 与移动。**
   - `late` 与 `~` 移动语义不进入 v1 稳定范围
   - 移动后状态后续评审

### 2.10 数组初始化与批量初始化

固定数组是整体值：

```c^
late int[5] a;
a = [1, 2, 3, 4, 5];   // 整体赋值，之后 a 已初始化
a[0] = 9;              // OK
```

逐元素写入不算整体初始化：

```c^
late int[5] a;
a[0] = 1;
a[1] = 2;
return a[0];           // Error：整个 a 仍未初始化
```

大数组使用重复数组字面量：

```c^
int[10000] zero = [0; 10000];
int[256] ones   = [1; 256];
```

- `N` 必须是编译期常量。
- `[value; N]` 生成 N 个相同元素。
- 全零/字节模式可以 lowering 为 `memset`；一般值使用循环。
- v1 限制为标量、POD、固定数组；复杂构造后续扩展。
- 大数组优先使用批量初始化；超大数组应使用堆上的 owning slice，而不是栈上的固定数组。

### 2.11 跨函数初始化：`out T&`

`out T&` 是**初始化引用**，不是值参数：

```c^
func fill(out int[5]& dst) {
    dst = [0; 5];   // 整体初始化
    dst[0] = 7;
}

func main() -> int {
    late int[5] a;
    fill(&a);       // 正常返回后 a 已初始化
    return a[0];
}
```

规则：

- `out` 只能修饰可变引用：`out T&`。
- `out T` 非法；`out T!&` 非法。
- 被调用方入口视为未初始化，不能读取，直到整体赋值。
- 所有正常返回路径必须完成整体初始化。
- 调用方只在正常返回后把实参标记为已初始化；异常路径不标记。
- `out T&` 可以绑定：`late` 变量、普通可变变量、`late let`。
- 不能绑定：`const`、`T!` 内容、已初始化的 `let`、临时值、单个元素。
- `out int[N]&` 初始化整个固定数组；`out int[]&` 只初始化切片描述符，不保证 backing array 元素已初始化。
- `int[]` 普通参数只是视图，不能用于初始化 backing array。
- v1 先限制为标量、固定数组、POD struct；带析构函数对象暂缓。

### 2.12 可变性与调用点

调用点规则：

```text
f(x)      值 / 只读引用，不会通过引用修改
f(&x)     可变引用 / 初始化引用，可能修改或初始化
```

- `T&` 可变引用，调用点必须 `&x`。
- `T!&` 只读引用，可以隐式传递 `f(x)`。
- `out T&` 初始化引用，调用点仍写 `&x`。
- 不引入 `mut`：`&` 已经是 C^ 的可变传参标记。
- 方法/指针的可变性由 `self!`、`T!^`、`T![]` 表达；调用点 `mut` 无法覆盖这些路径。

### 2.13 不采用的方案

- `out T`：看起来像值参数，容易与值拷贝混淆。
- `mut`：与 `&` 重复，且无法覆盖指针/方法修改。
- `late` 完全不检查：会让 `late` 变成隐式 unsafe。
- 逐元素 definite assignment：复杂度过高，v1 不做。
- 跨过程初始化推断：改用 `out T&` 显式契约。

## 3. 备选方案

### 方案 A：普通变量允许未初始化

优点：写法更短。
缺点：`late` 的价值被弱化，未初始化风险重新出现。

结论：不选。

### 方案 B：所有变量都必须初始化，`late` 是唯一例外（推荐）

优点：语义清晰，`late` 的职责明确。
缺点：部分代码需要写 `late`。

结论：选 B。

## 5. 开放问题确认结果

1. 非 `late` 局部变量必须初始化。
2. `late let int x;` 允许；`late var x;` 非法。
3. `late` 允许固定数组。
4. `late` 允许 trivial 类型。
5. 未初始化时赋值是构造；已初始化时是赋值。
6. 只有成功构造的对象才析构。
7. defer 引用 `late` 时，defer 注册点所有到达路径必须已初始化。
8. v1 允许循环内 `late` 只在循环体内使用；循环后使用需循环前已初始化。
9. `goto` 与 `late` 标记 experimental。
10. `catch` 可以作为初始化路径。
11. `late` 的 definite assignment 是变量级，不是逐元素。
12. 固定数组只有整体初始化/整体赋值才算初始化。
13. 跨函数初始化使用 `out T&`，不做过程间推断。
14. 大数组使用 `[value; N]` 批量初始化。
15. 不引入 `mut`，调用点仍用 `&` 表示可变引用/初始化引用。

## 6. 验收标准

- 非 `late` 局部变量未初始化时 semantic 报错
- `late` 变量使用前 definite assignment 检查
- `late` 对象只在成功构造后析构
- `try/catch` 中 `late` 初始化有测试
- `if/else` 中 `late` 初始化有测试
- `defer` 引用 `late` 有明确规则和测试
- `late` 数组整体赋值后可用，逐元素写入后仍报未初始化
- `[value; N]` 批量初始化有测试
- `out T&` 正常返回后调用方标记初始化，异常路径不标记
- `out T` / `out T!&` 被拒绝
- 文档中 `late` 语义与实现一致
