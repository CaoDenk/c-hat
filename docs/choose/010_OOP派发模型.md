## 1. 背景

C^ 当前 OOP 设计同时包含：

- 类 / 结构体 / 接口
- 单继承与多继承语法
- `virtual` / `override` / `abstract` / `final`
- 属性系统
- static 成员
- `self` / `self!` / `self~`
- `base` 成员访问与 `base(...)` 构造
- 泛型类/结构体
- RAII / 析构函数

但实现上：

- 继承字段布局已支持；
- 继承方法调用已支持；
- 属性 getter/setter 已支持；
- static 字段/方法已支持；
- 显式 `delete` 已调用析构函数；
- 虚方法动态派发、接口作为参数类型/动态调用、多继承 ABI 仍未实现。

因此需要先冻结 OOP 的长期模型，避免后续 ABI 反复变化。

---

## 2. 决策

### 2.1 实例关键字与基类访问

- 只使用 `self`，不使用 `this`。
- `self` 是当前实例引用。
- `self!` 是只读接收者。
- `self~` 是移动接收者（语法保留，语义后续实现）。
- `base` 用于访问基类子对象：`base.member`、`base.method()`。
- `base(...)` 只允许出现在构造函数初始化列表。
- `base` 只在派生类的实例方法/构造函数中合法；静态方法和无基类的类中报错。
- 裸 `base` 不作为普通值使用。

### 2.2 类型体系

- `class`：单实现继承 + 多接口实现。
- `struct`：值类型，不支持继承；可实现接口的语法层声明，但 v1 先按 struct 处理。
- `interface`：纯契约类型，不包含字段布局。
- 不保留多实现继承。文档中的多继承语法应收敛为“一个基类 + 多个接口”。
- 类名与结构体名在语义层是名义类型；继承关系在 `ClassType` 中显式记录。

### 2.3 继承布局

- 派生类布局 = 基类布局前缀 + 派生类字段。
- `structInfo_` 和 `memberIndices` 必须包含基类字段。
- 基类字段访问通过派生类对象指针加基类字段偏移完成。
- 单继承下，`base` 指针与 `self` 指针相同；多接口不改变实现基类布局。
- 空类仍保留占位字段，避免零大小类型。
- 布局由 semantic/codegen 共同保证，不靠 LLVM 猜测。

### 2.4 方法派发

- 默认方法是非虚方法，编译期静态派发。
- `virtual` 显式声明虚方法。
- `override` 必须写，用于检查签名与基类方法匹配。
- `final` 可阻止继续覆盖。
- `abstract` 方法没有函数体，类必须声明为 abstract。
- 有虚方法的类在对象头放 vtable 指针。
- 派生类 vtable 替换被覆盖的槽位，未覆盖的槽位继承基类。
- 非虚方法不进入 vtable。
- 静态方法不进入 vtable，也没有 `self`。

### 2.5 接口派发

- 接口值使用 fat pointer：`{object*, itable*}`。
- 类实现接口时生成 itable，包含接口方法对应的函数指针。
- 接口方法调用通过 itable 间接调用。
- v1 先支持接口方法声明、实现检查和具体类调用；接口值作为参数/返回值的动态派发列为后续实现。
- 接口继承通过 itable 组合或嵌套 itable 实现，不改变对象布局。

### 2.6 属性

- 属性不是字段，而是 `get_*` / `set_*` 方法的语法糖。
- `public get name -> T` 生成 `ClassName_get_name(self!) -> T`。
- `public set name(value: T)` 生成 `ClassName_set_name(self, T value) -> void`。
- 属性 getter 可以是虚方法；setter 可以是虚方法。
- 属性访问 `obj.prop` 降低为 getter 调用；`obj.prop = value` 降低为 setter 调用。
- 属性与字段同名时，属性优先。
- 继承属性的派发遵循方法派发规则。

### 2.7 静态成员

- static 字段是类级全局变量，不进入对象布局。
- static 方法没有 `self`，也不能访问实例成员。
- 静态方法通过类名调用：`ClassName.method(...)`.
- static 字段通过类名访问：`ClassName.field`。
- static 字段初始化 v1 只支持字面量；非字面量初始化延后。

### 2.8 构造与析构

- 构造函数语法：`ClassName(...)` 或 `func ClassName(...)`；推荐前者。
- 派生类构造函数必须显式或隐式调用基类构造函数。
- 执行顺序：基类构造函数 → 派生类字段初始化 → 派生类构造函数体。
- 析构函数语法：`~ClassName()`。
- 显式 `delete obj` 调用析构函数。
- 有虚方法的类自动具有虚析构语义；析构函数可以显式声明为 `virtual`。
- 析构函数不应抛异常；异常展开时析构函数参与 cleanup。
- 析构函数不能有参数、返回类型或访问修饰符之外的特殊语义。

### 2.9 访问控制

- `public` / `private` / `protected` / `internal`。
- 访问控制只在 semantic 层检查，不进入 ABI。
- 基类 protected 成员可被派生类访问。
- static 成员的访问规则与实例成员一致，但只能通过类名访问。

### 2.10 泛型与继承

- 泛型类/结构体单态化后，每个实例化类型都有自己的布局和方法集。
- 虚方法的 vtable 也是每个实例化类型独立生成。
- 接口实现检查在 generic instantiation 时进行。
- 继承关系不随泛型参数变化，但方法签名随类型参数变化。

## 3. ABI 与布局

### 3.1 对象布局

- 如果类有虚方法或虚析构：`{ vptr, base fields..., derived fields... }`
- 如果类没有虚方法：`{ base fields..., derived fields... }`
- 空类保留占位字段，避免零大小类型。
- 单继承下，基类字段从 offset 0 开始。

### 3.2 vtable 布局

- vtable 是函数指针数组。
- 第一个槽位建议为析构函数槽，后续为 virtual 方法槽。
- 派生类 vtable 替换被覆盖方法，未覆盖方法继承基类槽位。
- vtable 符号命名建议：`ClassName_vtable` 或 `ClassName__vtable`。

### 3.3 接口值布局

- 接口值为 `{object*, itable*}`。
- itable 包含接口方法对应的函数指针。
- 接口继承通过 itable 组合或嵌套 itable 实现。
- 接口值不改变对象布局。

### 3.4 方法 mangling

- 普通方法：`ClassName_methodName`
- 构造函数：`ClassName_ClassName`
- 析构函数：`ClassName_~ClassName`
- getter：`ClassName_get_prop`
- setter：`ClassName_set_prop`
- 泛型实例化：`ClassName__T` 风格，保持与现有泛型 mangling 一致。

### 3.5 已确认补充决策

1. **保留 `virtual` / `override` / `abstract` / `final` 全套。**
   - 默认静态派发。
   - `virtual` 开启动态派发。
   - `override` 必须写。
   - `abstract` 方法无函数体。
   - `final` 可用于类和方法。

2. **接口值使用 fat pointer `{object*, itable*}`。**
   - itable 包含接口方法函数指针。
   - 接口值不改变对象布局。

3. **有虚方法的类自动具有虚析构语义。**
   - 析构函数可以显式 `virtual`，但不再必需。
   - 通过基类指针 delete 时安全调用派生类析构。

4. **`base` 不允许裸值。**
   - `base` 只允许 `base.member` / `base.method()`。
   - `base(...)` 只允许构造函数初始化列表。
   - 静态方法、无基类上下文使用 `base` 报错。

5. **多继承语法收敛为“一个基类 + 多个接口”。**
   - `class Dog : Animal, Drawable, Resizable`
   - 第一个 class 是基类，后续必须是接口。
   - 不允许第二个实现基类。

6. **属性 getter/setter 允许 virtual。**
   - 属性本质是方法。
   - `virtual get` / `virtual set` 遵循方法派发。
   - 属性访问 lowering 为 getter/setter 调用。

7. **v1 不允许 struct 实现接口。**
   - struct 是值类型，接口值需要对象指针/itable。
   - 后续可通过取地址/装箱支持，但不进入 v1。

8. **泛型类 vtable 每个实例化独立。**
   - `Box<int>` 与 `Box<double>` 各自生成 vtable。
   - 泛型 mangling 与 ADR 017 一致。

9. **`base` 构造函数调用支持多参数。**
   - 语法：`: base(arg1, arg2, ...)`。
   - parser 需支持参数列表，而不是单表达式。

10. **`final` 可用于类和方法。**
    - `final class` 禁止继承。
    - `final method` 禁止覆盖。

## 4. 派发规则

### 4.1 静态派发

以下情况使用静态派发：

- 非 `virtual` 方法；
- 静态方法；
- 构造函数；
- 析构函数（非虚时）；
- 属性 getter/setter（非 virtual 时）；
- 通过具体类型调用的方法。

### 4.2 动态派发

以下情况使用动态派发：

- `virtual` 方法；
- 通过基类指针/引用调用的虚方法；
- 接口方法调用；
- 虚析构。

### 4.3 继承方法调用

- `obj.method()` 如果 `method` 是派生类方法，调用派生类实现；
- 如果 `method` 是继承自基类的方法，调用基类实现；
- 如果 `method` 是 virtual，通过 vtable 调用；
- 如果 `method` 是 non-virtual，编译期绑定。

### 4.4 `base` 与 `self`

- `self` 是当前对象指针。
- `base` 是基类子对象视图；单继承下与 `self` 同址。
- `base.method()` 优先查找基类方法；如果基类方法是 virtual，仍通过 vtable 调用。
- `self.method()` 优先查找派生类方法。

## 8. 开放问题确认结果

1. 保留 `virtual` / `override` / `abstract` / `final` 全套。
2. 接口值使用 fat pointer `{object*, itable*}`。
3. 有虚方法的类自动具有虚析构语义。
4. `base` 不允许裸值，只允许成员访问和构造函数调用。
5. 多继承语法收敛为“一个基类 + 多个接口”。
6. 属性 getter/setter 允许 virtual。
7. v1 不允许 struct 实现接口。
8. 泛型类 vtable 每个实例化独立。
9. `base(...)` 支持多参数。
10. `final` 可用于类和方法。
